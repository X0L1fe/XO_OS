## Исправлено дублирование событий в Google Calendar

### Изменения в файле `app/google_calendar/service.py`:

1. **Удален дублирующий блок обработки созданных уроков** в методе `sync_changes`. Ранее блок обработки `diff.created` был повторен дважды, что приводило к двойной попытке создания событий для каждого нового урока.

2. **Добавлена проверка на существование `google_event_id` перед созданием события** для созданных уроков. Хотя урокам из `diff.created` теоретически не должно быть `google_event_id`, эта проверка делает процесс идемпотентным и предотвращает создание дубликатов в случае, если урок уже имеет идентификатор события (например, из-за повторной обработки).

3. **Исправлена опечатка в методе `sync_lesson`**: заменено использование неопределенной переменной `lesson_data` на `lesson_db` в сообщении об успешном создании события.

### Как это решает проблему дублирования:

- Теперь каждый урок из `diff.created` обрабатывается ровно один раз.
- Если урок уже имеет `google_event_id` (что маловероятно для newly created уроков, но возможно при повторной обработке), событие не создается повторно.
- Блоки обработки `updated`, `moved`, `deleted` и `unchanged` оставлены без изменений, так как они не содержали дублирования и уже были идемпотентны благодаря проверкам и обновлению поля `last_synced_at`.

### Дополнительные рекомендации для полной уверенности:

- Убедитесь, что у бота есть только один экземпляр running (чтобы избежать параллельной обработки одного и того же обновления Telegram).
- При необходимости можно добавить в бота простую дедупликацию по хешу содержимого файла или ID сообщения Telegram на короткий промежуток времени, чтобы исключить обработку одного и того же файла несколько раз из-за повторной доставки обновлений Telegram.

После этих изменений при получении одного .ics файла бот должен создавать ровно одно событие в Google Calendar для каждого урока, а не два.
